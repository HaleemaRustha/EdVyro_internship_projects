
# Task 2 — Local Reconnaissance and Attack Surface Map

## Objective

Perform controlled reconnaissance against an authorized local OWASP Juice Shop instance and document the discovered services, application endpoints, headers, visible data, and potential security risks.

All testing was performed against the local lab target:

```text
http://127.0.0.1:3000
````

No public or third-party systems were scanned or tested.

---

## 1. Target and Scope

| Item             | Details                        |
| ---------------- | ------------------------------ |
| Target           | OWASP Juice Shop               |
| Target Address   | `127.0.0.1:3000`               |
| Environment      | Kali Linux VM                  |
| Deployment       | Docker                         |
| Protocol         | HTTP                           |
| Scope            | Local Juice Shop instance only |
| External Systems | Out of scope                   |

The target was confirmed to be accessible locally before reconnaissance.

---

## 2. Target Confirmation

The following command was used to confirm that the local web application was responding:

```bash
curl -I http://127.0.0.1:3000
```

Observed response:

```text
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 9393
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
Access-Control-Allow-Origin: *
X-Recruiting: /#/jobs
```

This confirmed that the target was serving an HTTP web application on port `3000`.

---

## 3. Service Enumeration

Nmap was used to identify the service running on the authorized local port:

```bash
sudo nmap -sV -p 3000 127.0.0.1
```

### Result

```text
PORT     STATE SERVICE VERSION
3000/tcp open  ppp?
```

Nmap identified port `3000/tcp` as open but could not determine the exact service/version automatically.

The HTTP response and application title identified the service as the OWASP Juice Shop web application.

---

## 4. Frontend Asset Discovery

The initial HTML page was inspected for JavaScript resources:

```bash
curl -s http://127.0.0.1:3000 | grep -oE 'src="[^"]+\.js[^"]*"' | head -20
```

Observed JavaScript files:

```text
polyfills.js
scripts.js
main.js
```

These files represent the frontend resources loaded by the application.

The initial HTML also contained references to:

```text
assets/public/favicon_js.ico
styles.css
```

The application uses dynamically rendered frontend content, so application routes and form elements were not directly visible through simple HTML extraction.

---

## 5. API Endpoint Discovery

Browser Developer Tools were used to observe API requests generated by the running application.

### Endpoint 1 — Challenges

```text
GET /api/Challenges
```

A direct request was made using:

```bash
curl -s http://127.0.0.1:3000/api/Challenges | head -c 500
```

The endpoint returned JSON with challenge-related information, including fields such as:

```text
id
key
name
category
description
difficulty
mitigationUrl
solved
```

### Endpoint 2 — Challenges with Query Parameter

The browser was observed requesting:

```text
GET /api/Challenges/?name=Score Board
```

The request returned:

```text
304 Not Modified
```

This demonstrates that the endpoint accepts a `name` query parameter.

### Endpoint 3 — Quantity API

The browser was also observed requesting:

```text
GET /api/Quantitys/
```

The request returned:

```text
304 Not Modified
```

The response contained:

```text
status: "success"
```

and a data collection containing 56 records.

Observed fields included:

```text
ProductId
id
quantity
```

Example observations included product IDs and corresponding quantity values.

## 6. HTTP Security Header Observations

The following headers were observed during reconnaissance:

| Header                        | Observation                |
| ----------------------------- | -------------------------- |
| `Access-Control-Allow-Origin` | `*`                        |
| `X-Content-Type-Options`      | `nosniff`                  |
| `X-Frame-Options`             | `SAMEORIGIN`               |
| `Feature-Policy`              | `payment 'self'`           |
| `X-Recruiting`                | `/#/jobs`                  |
| `Content-Type`                | `text/html; charset=UTF-8` |

### Interpretation

`X-Content-Type-Options: nosniff` and `X-Frame-Options: SAMEORIGIN` are security-related controls and were recorded as observations rather than vulnerabilities.

The wildcard CORS value:

```text
Access-Control-Allow-Origin: *
```

was recorded as a configuration observation requiring further review. Its presence alone does not establish a vulnerability.

## 9. Risk Hypotheses

The following are potential areas for further security review. They are hypotheses and are not being classified as confirmed vulnerabilities based solely on reconnaissance.

| Observation                                                   | Potential Risk          | Reason for Review                                                              |
| ------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------ |
| `Access-Control-Allow-Origin: *`                              | CORS configuration risk | Wildcard cross-origin access may be inappropriate for some sensitive endpoints |
| `/api/Quantitys/` exposes product quantities                  | Information exposure    | Inventory-related data is directly returned by an API endpoint                 |
| `/api/Challenges/?name=Score Board` accepts a query parameter | Input validation risk   | Server-side handling and validation of the `name` parameter should be reviewed |
| `/api/Challenges` returns detailed challenge metadata         | Information exposure    | API provides application/challenge information directly to clients             |
| Port `3000/tcp` is exposed locally                            | Attack surface          | Web application service is reachable within the authorized lab environment     |

## 12. Conclusion

The reconnaissance phase identified an HTTP web application running on TCP port `3000` and confirmed the presence of multiple REST API endpoints.

The main observed attack-surface components were:

* HTTP web service
* JavaScript frontend
* Challenges API
* Quantity API
* Query-parameter based API request
* HTTP security headers
* Application data returned through API responses

All reconnaissance activities were restricted to the authorized local OWASP Juice Shop instance at `127.0.0.1:3000`.
